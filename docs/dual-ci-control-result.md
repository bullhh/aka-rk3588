# 双客户机 CI 完成协议

## 1. 范围与责任

本次复用 `robot_runtime_config_v1.h` 的 48 字节消息和现有双向 IVC，新增控制结果查询，
使 Linux/Starry 的 CI 结果不仅证明场景已发送，还证明 Zephyr 控制状态机成功结束。
不增加通道、宿主线程或全局控制台显示模式。普通运行和旧配置消息保持兼容。

### 1.1 启动

仅机器人 CI 根文件系统安装交互 Shell 就绪标志，两个 board TOML 观察各自标志后
启动用户程序。发送方用同一个随机会话编号执行 BEGIN/CHUNK/COMMIT；BEGIN 以总超时
等待 Zephyr，迟到的同会话旧 ACK 被跳过，拒绝和协议错误不可伪装为成功。
性能计时在配置完成和摄像头预热后开始。

### 1.2 控制完成

感知程序完成 62 秒场景后，查询 `CONTROL_FINISH`，最多等待 10 秒，期间继续发送最后
场景以维持输入看门狗。Zephyr 用已应用会话编号和配置 CRC 拒绝旧查询。
返回 `CONTROL_RESULT` 的 pending/success/failed 及完成周期、检查位、控制状态和错误码。
重复查询仅生成快照，不重复动作或累计周期。

## 2. 所有权与失败

`robot_controller` 在现有 `controller_lock` 下维护动作、故障和完成状态。
IVC 主循环在锁内取快照，锁外发送，定时回调不操作 IVC。主循环仍是唯一的消息收发者。

### 2.1 成功边界

成功要求 CI 周期结束、机械臂终点反馈通过、停车命令成功且没有 FAULT。
不得将失败停车后的 FAULT 覆盖成 TEST_COMPLETE。结果不声称验证了真实抓球、
轮速反馈或看门狗实验。配置重新应用会清零周期和故障，旧结果不跨会话保留。

### 2.2 验证与回滚

CI 仍只检查感知端日志：28/19 FPS、完整流程、匹配本次配置会话的控制成功消息和
零退出码，最后 sync。旧 Zephyr 不支持完成消息时必须失败。部署时备份感知二进制、
Zephyr 镜像、脚本和 Shell 配置，同步两端升级；回滚也按整组进行。模型与校准不替换。
测试覆盖停车失败、pending、旧会话、重复查询、配置重置、丢失或错误回复、启动顺序
及 Linux/Starry 两种实机完整流程。真实执行器反馈由板卡测试验证，主机替身只验证状态机。
