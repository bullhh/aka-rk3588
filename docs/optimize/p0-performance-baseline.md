# P0 性能基线（Linux，640×640 模型）

## 结论

2026-07-28 在 `10.3.10.60` 管理的三足机器人上完成了一次真实闭环：

```text
发现并靠近球
→ 夹球成功（holding=yes）
→ 搜索并对齐桶
→ 放球成功
→ 返回 CHASE_BALL
```

P0 的统计与日志限流功能工作正常。当前 `640×640` RKNN 模型在 Linux 下的稳定视觉处理能力约为 **26.3 FPS**，主要耗时是 RKNN 推理，平均约 **33.6 ms/帧**。

## 稳态视觉基线

以下两个窗口位于一次放球完成后的找球阶段，不包含机械臂长动作，适合作为后续 P1 和 640×480 模型优化的对比基准。

| 指标 | 窗口 1 | 窗口 2 | 基准值 |
| --- | ---: | ---: | ---: |
| 窗口长度 | 10.01 s | 10.02 s | 20.03 s |
| 摄像头帧率 | 29.68 FPS | 30.05 FPS | 29.87 FPS |
| 有效处理帧率 | 26.29 FPS | 26.36 FPS | 26.31 FPS |
| 覆盖帧数 | 33 / 297 | 37 / 301 | 70 / 598（11.7%） |
| 单帧平均耗时 | 38.04 ms | 37.94 ms | 37.99 ms |
| 单帧 P50 | 37.20 ms | 37.22 ms | 约 37.2 ms |
| 单帧 P95 | 37.32 ms | 41.39 ms | 37.3～41.4 ms |
| JPEG 解码 | 3.74 ms | 3.20 ms | 3.47 ms |
| letterbox 复制 | 0.129 ms | 0.121 ms | 0.125 ms |
| RKNN 输入 | 0.30 ms | 0.25 ms | 0.28 ms |
| RKNN 推理 | 33.09 ms | 34.02 ms | 33.56 ms |
| RKNN 输出 | 0.12 ms | 0.11 ms | 0.12 ms |
| 后处理 | 0.029 ms | 0.023 ms | 0.026 ms |
| 控制计算 | 0.118 ms | 0.113 ms | 0.116 ms |

由此可见：

- 摄像头稳定提供约 30 FPS，不是当前主要瓶颈。
- RKNN 推理占稳定单帧耗时的约 88%，是有效帧率低于 30 FPS 的主要原因。
- JPEG 解码约占 9%，是第二个值得优化的环节。
- letterbox 复制、模型输入、输出和后处理耗时都较小，单独优化收益有限。
- 单槽采集缓冲区覆盖约 11.7% 的输入帧，但程序始终处理最新帧，不会积压旧画面；这与 30 FPS 摄像头和约 26.3 FPS 处理能力相符。

## 完整闭环数据解释

闭环期间还出现了三个非稳态窗口：

| 阶段 | 窗口 | 有效帧率 | 说明 |
| --- | ---: | ---: | --- |
| 夹球 | 21.00 s | 5.67 FPS | 包含约 16.18 s 的机械臂阻塞动作，不能用于评价视觉性能 |
| 找桶 | 10.04 s | 30.09 FPS | 不运行 RKNN；JPEG 相关平均耗时 11.78 ms，反映当前桶状态存在重复解码 |
| 放球 | 17.74 s | 3.10 FPS | 包含约 15.94 s 的放球机械臂动作，不能用于评价视觉性能 |

`unaccounted` 在夹球、放球窗口分别达到 134.65 ms/帧和 297.22 ms/帧，原因是机械臂动作会阻塞主循环，而 P0 当前只统计视觉与单帧控制阶段。该值用于区分“视觉变慢”和“主循环正在执行长动作”，不是漏帧故障。

## P0 实现内容

- 使用 `CLOCK_MONOTONIC` 记录耗时，摄像头和 NPU 预热后开始统计。
- 每 10 秒打印用户态取帧率、有效帧率、处理能力和分阶段耗时。
- 统计单帧平均值、P50、P95 和最大值。
- 统计同步 UVC 取帧、内存复制耗时。
- 记录 JPEG 解析/解码、letterbox、RKNN 输入/运行/输出、后处理和控制耗时。
- 连续球/桶位置和轮速日志默认每秒最多输出一次；错误、超时和重试仍立即输出。
- 机械臂步骤只在步骤发生变化时输出，不再按控制周期重复打印。
- 删除高频普通状态日志周围无意义的 `dup2` 切换；RKNN 噪声抑制保持不变。

状态日志频率可在运行时调整：

```bash
# 默认：每秒一次
AKA_STATE_LOG_INTERVAL_MS=1000 ./run_lekiwi_full.sh

# 调试瞬时控制行为：恢复逐帧状态日志
AKA_STATE_LOG_INTERVAL_MS=0 ./run_lekiwi_full.sh
```

## 后续对比规则

P1 和 640×480 模型均使用相同机器人位置、模型场景和运行参数，至少采集 6 个不含机械臂动作的 10 秒窗口。重点比较：

```text
effective_fps
frame_ms avg / P95 / max
jpeg_decode
letterbox_copy
rknn_run
captured / processed
完整夹球和放球是否成功
```

含夹球或放球动作的窗口单独分析，不与稳态视觉窗口求平均。
