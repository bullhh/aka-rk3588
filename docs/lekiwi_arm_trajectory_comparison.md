# LeKiwi 机械臂轨迹实机对比

测试日期：2026-07-17  
参考版本：[Desktop-Wanderer c7da333](https://github.com/my-robot-army/Desktop-Wanderer/commit/c7da3337ef476c9bccf994bca5e84ebf792e7760)

## 1. 测试方法

在 Orange Pi 5 Plus 的 Linux 下，通过同一个 aka Feetech TTY 后端、同一份舵机标定和
20 Hz 控制周期，分别运行当前轨迹和 Desktop-Wanderer 参考轨迹。每条轨迹运行3次，
逐周期记录6个关节的实际反馈角度，结束后立即执行 `torque-off`。

没有直接运行参考仓库的完整 Python 硬件程序：它会重新配置舵机模式、PID和 LeRobot
标定，并同时初始化相机。为排除硬件初始化和标定差异，本次只移植其
`CATCH_ACTION` 坐标、顺序和直接 GRAB→LIFT 路径，实际驱动仍使用已经验证的 aka
通信和安全 HOME。对比程序和日志均在 `/tmp`，未替换正式 `build/tennis`。

测试时未放置网球，因此这里只比较姿态、轨迹和停止效果，不评价实际夹取成功率。

## 2. 两条轨迹

| 项目 | 当前轨迹 | Desktop-Wanderer 参考轨迹 |
| --- | --- | --- |
| PRE_GRAB | `(0.09, 0.1211)` | `(0.14, 0.1211)` |
| GRAB | `(0.09, -0.08)` | `(0.14, -0.05)` |
| 闭合后 | 先 CLEAR 回 PRE_GRAB | 直接抬升 |
| LIFT | `(-0.10, 0.20)`，腕部连续插值 | `(-0.10, 0.20)`，腕部随 IK 变化 |
| 阶段数 | 13 | 12 |

参考 GRAB→LIFT 线段离二连杆原点最近约 `6.6 cm`；当前 GRAB 坐标若直接抬升只剩
约 `3.0 cm`，所以当前轨迹不能简单删除 CLEAR。

## 3. 实机结果

以下峰值速度根据20 Hz反馈相邻差分估算，并排除了共同的 HOME 阶段。

| 指标 | 当前轨迹 | 参考轨迹 |
| --- | ---: | ---: |
| 成功轮次 | 3/3 | 3/3 |
| 平均总时长 | 8.91 s | 8.15 s |
| 肩部峰值速度 | 107.3 °/s | 146.2 °/s |
| 肘部峰值速度 | 74.6 °/s | 101.4 °/s |
| 腕部峰值速度 | 110.9 °/s | 127.1 °/s |
| 肩部累计变化 | 203.5° | 198.2° |
| 肘部累计变化 | 137.9° | 156.3° |
| 腕部累计变化 | 212.5° | 161.0° |

关键姿态为三轮实际反馈平均值：

| 时刻 | 轨迹 | 肩部 | 肘部 | 腕部 |
| --- | --- | ---: | ---: | ---: |
| GRAB结束 | 当前 | 41.4° | 54.3° | -13.0° |
| GRAB结束 | 参考 | 32.5° | 38.0° | 14.3° |
| 最终停止 | 当前 | -74.1° | -16.9° | 70.1° |
| 最终停止 | 参考 | -76.5° | -15.6° | 90.3° |

两条轨迹最终腕部目标都约为 `68.5°`。当前停止误差约 `1.5°`，参考轨迹仍有约
`21.8°` 误差，原因是参考序列最后只执行固定4个控制周期便结束，腕部没有充分收敛。

## 4. 对比结论

- 参考轨迹的夹球姿态更舒展：肩、肘弯曲更小，腕部保持正角度；这是它看起来更自然
  的主要原因，而不只是控制频率更高。
- 对比时的旧版 `(0.09, -0.08)` 抓取点过深、过靠近底座，导致肩肘折叠且腕部变为负角度，
  所以夹球姿态仍不美观。
- 对比时的旧版 CLEAR 和 LIFT 腕部插值有效：抬升速度更低，最终停止角度也更接近目标。
- 参考轨迹更短，但直接 GRAB→LIFT 的肩、肘峰值速度更高，且停止时腕部未到位，不能
  整体替换当前轨迹。

## 5. 优化结果

已保留安全 HOME、CLEAR 和20 Hz反馈控制，并采用折中坐标：

```text
pre_grab_x = 0.120
pre_grab_y = 0.1211
grab_x = 0.120
grab_y = -0.060
```

该点的理论 IK 约为肩部 `37.7°`、肘部 `42.1°`、腕部 `0.2°`，处于旧姿态和参考
姿态之间。MOVE_TO 和腕部阶段也已由固定周期结束改为等待实际反馈收敛，单阶段超过
100周期会输出全部关节残差并失败。实测发现 CLEAR 的肘部静差约5.2°，因此非夹爪
关节在残差小于6°时直接发送最终目标，之后 Linux 连续3轮和 Starry 1轮通过，Linux
单轮约10.7-10.9秒。

随后根据实机手动记录结果，将不自然的“平转回零→笛卡尔LIFT→腕部调整”替换为
CLEAR后直接进入CARRY。只采用最有参考价值的车轮启动前姿态，手动记录的夹爪值和
抓球点均未使用：

```text
carry_shoulder_pan  = -11.3
carry_shoulder_lift = -18.3
carry_elbow_flex    = -45.0
carry_wrist_flex    = 51.8
carry_wrist_roll    = 0.1
```

CARRY使用40个20 Hz周期的五次 S 曲线，之后保持10周期。Linux连续3轮、Starry 1轮
通过，单轮约10.1-10.6秒；最终原始位置与手动记录值约差1-15个编码值，动作结束后
9个电机速度均为0。

测试没有放置网球。若现场夹爪够不到球，应优先调整机器人停车距离，使球进入更自然的
机械臂工作区，而不是继续把机械臂折向底座。
